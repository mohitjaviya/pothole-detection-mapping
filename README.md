# Road Pothole Detection & Geo-Tagged Mapping

## Overview

Semester 7 Computer Vision project. Detects potholes in dashcam video using
YOLOv8, tracks them so each pothole is counted once, estimates severity,
attaches GPS coordinates, and shows them on an interactive map.

## Stack

- Python 3.10+
- Ultralytics YOLOv8 (detection + built-in ByteTrack tracking)
- OpenCV (video I/O, classical baseline)
- pandas, numpy
- Folium (map + heatmap)
- Streamlit (demo dashboard)

## Main flow

```
dashcam video + GPS CSV -> YOLO detection -> tracking (unique IDs)
-> severity (by bbox area) -> match timestamp to GPS -> Folium map + CSV report
```

## Environment rules

- Training happens on Google Colab / Kaggle (GPU). Do NOT assume a local GPU.
- Local code must run on CPU (use yolov8n, resize frames, allow frame skipping).
- Training logic goes in `src/train.py`; `notebooks/train_colab.ipynb` wraps
  it for Colab. Trained weights are downloaded into `models/best.pt`.
- Never commit `data/`, `models/`, `outputs/` or `venv/`.

## Project structure

- `data/` — never committed. `raw/` (pothole image dataset, YOLO format),
  `processed/` (extracted frames), `sample_videos/` (short dashcam clips),
  `gps_logs/` (one CSV per video: `timestamp_sec, latitude, longitude`)
- `src/` — one job per module, each with a `main()` for CLI use:
  - `config.py` — shared paths, thresholds, confidence, frame skip (single source of truth)
  - `baseline.py` — classical OpenCV baseline to compare against YOLOv8
  - `train.py` — dataset prep + fine-tuning logic (executed on Colab via the notebook)
  - `detect.py` — frame extraction + YOLOv8 detection + ByteTrack -> raw track log
  - `tracker.py` — collapses the track log into one record per unique pothole
  - `severity.py` — bbox area as fraction of frame -> small / medium / large
  - `geotag.py` — matches frame timestamps to GPS rows -> attaches lat/lon
  - `map_builder.py` — Folium map (severity-colored markers + heatmap) + CSV report
  - `pipeline.py` — **one command** for the five stages above (detect -> map)
  - `evaluate.py` — baseline vs YOLOv8n vs YOLOv8s, broken down by day/night/wet/blur
  - `robustness.py` — dim / blur / noise / motion-blur sweep on one clip -> `reports/robustness.csv`
- `configs/` — static YAML (e.g. `bytetrack.yaml` tracker tuning); `data.yaml`
  is generated by `train.py` into the dataset root (never committed)
- `app/` — `streamlit_app.py` (demo dashboard: video -> map, table, severity chart)
- `notebooks/` — `train_colab.ipynb` (dataset download, run `src/train.py`, export `best.pt`)
- `models/` — `best.pt` (never committed)
- `outputs/` — annotated videos, maps, per-run CSVs (never committed)
- `reports/` — evaluation figures and metric tables for the semester report
- `tests/` — fake-data fixtures (`make_*.py`) + one test per module (committed,
  no dataset, no GPU)

## Conventions

- Use `pathlib` for paths and type hints on all functions.
- Keep each module in `src/` focused on one job, with a `main()` for CLI use.
- Config (paths, thresholds, conf, frame skip) lives in `config.py`,
  not hardcoded.
- GPS CSV format: `timestamp_sec, latitude, longitude`
- Severity: small / medium / large from bbox area as a fraction of the frame.
- Write short comments explaining the CV logic (this is a student project
  that will be explained to faculty).

## GPS source (step 4 decision)

- **Primary:** phone GPS logger app exporting a CSV with
  `timestamp_sec, latitude, longitude` (`timestamp_sec` = Unix epoch seconds;
  ISO 8601 strings are converted on load, naive datetimes assumed
  Asia/Kolkata +05:30). One CSV per clip in `data/gps_logs/`.
- **Fallback / demo:** simulated route — `tests/make_fake_data.py` writes a
  1 Hz northbound route from Ahmedabad, so the whole back half of the pipeline
  runs and demos without any recorded GPS.
- **Sync:** the video start is either parsed from a dashcam-style filename
  (`YYYYMMDD_HHMMSS.mp4`) or passed explicitly (`geotag.py --start-time`).
  Both GPS forms and both start-time forms are already supported.

## Running the pipeline

Run from the repo root (Windows: use `venv\Scripts\python.exe`).

### One command (recommended)

```bash
# video + GPS CSV -> every stage's CSV + map in outputs/
python -m src.pipeline data/sample_videos/clip_a.mp4 \
    --gps data/gps_logs/clip_a.csv \
    --start-time "2026-10-28 10:00:00+05:30"

# no GPS CSV -> a SIMULATED route is generated (wiring demo, not your location)
python -m src.pipeline data/sample_videos/clip_a.mp4 --frame-skip 5 --no-video

# skip detection entirely (no torch, no weights) — reuse an existing track log
python -m src.pipeline data/sample_videos/clip_a.mp4 \
    --track-log outputs/track_log_clip_a.csv

# refuse to invent coordinates when there is no GPS CSV
python -m src.pipeline data/sample_videos/clip_a.mp4 --no-simulated-gps
```

Outputs land in `outputs/` as `<clip>_track_log.csv`,
`<clip>_pothole_events.csv`, `<clip>_pothole_events_severity.csv`,
`<clip>_pothole_events_geo.csv`, `<clip>_map.html` (plus
`<clip>_simulated_route.csv` when the fallback route was used).

### Stage by stage

```bash
# 0. tests — fake data only, no model, no GPU
python tests/make_fake_video.py
python tests/make_fake_data.py
python tests/make_fake_track_log.py
python tests/make_fake_eval_data.py
python tests/test_detect.py
python tests/test_tracker.py
python tests/test_chain.py
python tests/test_evaluate.py
python tests/test_app.py
python tests/test_pipeline.py
python tests/test_robustness.py

# 1. detect + track (needs ultralytics + weights)
python -m src.detect data/sample_videos/clip_a.mp4 --frame-skip 2 --conf 0.25

# 2. one event per unique pothole
python -m src.tracker outputs/track_log_clip_a.csv

# 3. severity
python -m src.severity outputs/pothole_events.csv

# 4. lat/lon (phone GPS CSV, or --fps for a fake clip)
python -m src.geotag outputs/pothole_events_severity.csv data/gps_logs/clip_a.csv \
    --start-time "2026-10-28 10:00:00+05:30"

# 5. map
python -m src.map_builder outputs/pothole_events_severity_geo.csv --heatmap

# 6. evaluation (see below)
python -m src.evaluate --manifest data/eval_manifest.csv --events outputs/pothole_events.csv

# 7. robustness sweep (dim / blur / noise / motion blur) -> reports/robustness.csv
python -m src.robustness data/sample_videos/clip_a.mp4 --frame-skip 5
```

## Evaluation (step 10)

Two independent jobs, because they need different ground truth.

**Counting** needs one row per clip — the manual pothole count and the driving
condition. Put it at `data/eval_manifest.csv` (owner data, gitignored):

```csv
source,condition,gt_count
clip_a.mp4,day,4
clip_b.mp4,night,3
clip_c.mp4,wet,2
```

- `source` — video filename, exactly as it appears in the track log's `source`
  column
- `condition` — one of `day`, `night`, `wet`, `blur` (`config.EVAL_CONDITIONS`)
- `gt_count` — potholes a human counts in that clip

```bash
python -m src.evaluate --manifest data/eval_manifest.csv --events outputs/pothole_events.csv
```

**Detection quality** needs labelled images: the classical baseline is scored
against YOLO `.txt` labels (IoU 0.5), and the YOLOv8 models go through
`ultralytics val()` for mAP. Prepare the split locally first (CPU only, no
training):

```bash
python -m src.train --data-only
```

```bash
python -m src.evaluate \
    --images data/processed/ivcnz/test/images \
    --labels data/processed/ivcnz/test/labels \
    --data-yaml data/processed/ivcnz/data.yaml \
    --models yolov8n yolov8s
```

Both modes write into `reports/` (committed): `detection_metrics.csv`,
`eval_comparison.csv`, `eval_comparison.png`, `count_metrics.csv`,
`count_by_condition.csv`, `eval_summary.md`, and
`eval_counts_by_condition.png`.

`eval_comparison.csv` is the one row per method table (tp / fp / fn +
precision / recall / F1); when a method reports P and R but no F1 (ultralytics
`val()` reports P/R/mAP), F1 is derived as their harmonic mean.

Pre-computed predictions can be scored locally with **no model and no torch** —
handy when the detectors run on Colab and only their boxes come back:

```bash
python -m src.evaluate --images data/processed/ivcnz/test/images \
    --labels data/processed/ivcnz/test/labels \
    --methods baseline=outputs/preds_baseline.csv yolov8n=outputs/preds_yolov8n.csv
```

Each `name=path` is either a CSV with columns `image, x1, y1, x2, y2`
(absolute pixels) or a folder of YOLO `.txt` files.

Note: the baseline has no confidence score, so it has no PR curve — its mAP is
`-` by design. It is compared on precision/recall/F1 at IoU 0.5, which is the
fair comparison for a threshold-free detector.

## Robustness sweep

`robustness.py` re-runs detection on degraded copies of one clip (brightness
down, Gaussian blur, pixel noise, horizontal motion smear), applying the
degradation per frame inside the detection loop so the model, frame skip and
clip are identical across conditions. It writes `reports/robustness.csv` with
detections, unique tracks and retention versus the clean pass:

```bash
python -m src.robustness data/sample_videos/clip.mp4 --frame-skip 5
python -m src.robustness data/sample_videos/clip.mp4 --write-videos   # keep the clips
```

The committed table was produced on `clip_synthetic_photos.mp4` (the wiring
clip), so it shows the sweep works and how the model degrades — it is **not** a
dashcam robustness result. Re-run it on real footage before quoting it.

## Dashboard (step 11)

```bash
venv\Scripts\streamlit.exe run app\streamlit_app.py
```

Opens on <http://localhost:8501>. In the sidebar: pick a clip from
`data/sample_videos/` (or upload one), a GPS CSV from `data/gps_logs/` (or
upload one), the weights (`models/best.pt` by default), then the detection
settings (confidence, frame skip) and the tracker settings (min frames per
pothole, merge gap, merge IoU). Press **Run pipeline**; the page shows unique
potholes, geotagged count, the severity chart, the Folium map, the annotated
clip, the events table, and CSV downloads.

**Demo mode** — press **Load demo data (no model needed)** to render the whole
dashboard from six synthetic events plus a simulated route. No clip, no weights,
no GPU, no real GPS: useful for a screenshot or for explaining the UI when the
laptop has no model. It is labelled as simulated on the page.

The app writes into `outputs/app/`. Without a GPS CSV it still detects, tracks
and grades severity — it just cannot put potholes on a map, and it never
invents coordinates. All non-UI logic is plain functions (`run_pipeline`,
`build_demo_result`, `severity_counts`), so `tests/test_app.py` drives the whole
chain headlessly with a stub model; `run_pipeline` delegates to
`src/pipeline.py`, so the CLI and the dashboard cannot drift apart.
